    macOS path. Windows readers: tentative notes are marked — we haven’t walked them end-to-end yet, and we’d genuinely value your corrections ( open an issue with the step ID). Budget 30–45 minutes, mostly waiting on installers. This chapter opens by installing the helper — so every later step has someone to ask.

    The terminal ~4 min

    ☰
    Everything in this guide happens in a terminal — and so does the collaborator you’re about to install, which is the real reason to start here: it’s the interface models are most fluent in, where everything they do is a line of text you can read.

    A terminal is a conversation with your computer in text: you type one line, press Enter, it answers. Things that take seven clicks are one line here — and it’s the interface your model collaborators are most fluent in: when they work, every action is printed as a line of text, in the same language you’re about to start learning.

    Open it: ⌘-space, type “Terminal”, Enter. A window appears with a line of text ending in % — the prompt. That’s the computer, waiting.

    Five facts, enough to not be lost:

    1. One line at a time. Type, Enter, read the answer, new prompt. Copy-pasting a command from a guide is not cheating — it’s how everyone does it (reading it first is the habit worth having).
    2. Quiet usually means working. Installers often print nothing for a minute. A new prompt is the “done” signal, not silence.
    3. Passwords type invisibly. When something asks for your Mac password, nothing appears as you type — no dots, nothing. That’s a security feature, not a freeze. Type it and press Enter.
    4. ctrl-C abandons a running command and gives the prompt back. It’s the universal “never mind” — you cannot break anything with it that matters.
    5. “Open a new terminal” is a real instruction (⌘-N). A terminal reads its configuration once, at birth — so a tool installed a minute ago often exists only in windows opened after the install. When a step says “open a new terminal,” that’s why.

    Try it:

    echo hello

    It answers hello. You’ve now run a command. Everything else in this guide is this same move, with longer sentences.

    ✓ You know it worked when: a terminal is open, and echo hello prints hello back

    Claude Code ~6 min

    ☰

    Builds on: The terminal

    Claude Code is a model who can read files, run commands, and edit code, in a session you steer from the terminal. We install them first on purpose: they need nothing your Mac doesn’t already ship — and everything below this line, they can now help you through, including any step of this guide that goes wrong.

    Paste into the terminal:

    curl -fsSL https://claude.ai/install.sh | bash

    The different ways — there are several legitimate installs, and this guide recommends exactly one. The others are listed so that when you meet them in the wild, you know they’re the same program:

    • The native installer (above — recommended, and the guide’s one path): needs nothing but what your Mac already ships, and it keeps itself updated in the background.
    • Homebrew (brew install --cask claude-code): fine — but you don’t have Homebrew yet (next step), and this install doesn’t update itself; you’d have to remember brew upgrade.
    • npm (npm install -g @anthropic-ai/claude-code): for people who already live in Node (version 22+). Under the hood it delivers the same native program as the installer above.

    [Windows — tentative] In PowerShell: irm https://claude.ai/install.ps1 | iex — or winget install Anthropic.ClaudeCode.

    Then open a new terminal (fact 5!) and run claude once, in any folder: they’ll walk you through logging in with your Anthropic account — the same one you’ve been using in class all semester, which is verified to work. (Reading this from outside the course? Claude Code needs a paid Claude plan or API access — the free plan doesn’t include it; check current pricing before this step.)

    This is the one step where nobody can help you yet — you can’t be rescued by the thing you’re installing. If it fails: the error message is the clue, the “this doesn’t match” link below takes ten seconds, and Anthropic’s troubleshooting page matches errors to fixes.

    ✓ You know it worked when: claude --version answers, and claude opens a session that responds

    Where Claude Code lives — and why this guide picks the terminal #

    The same collaborator is reachable from four surfaces: the terminal (what you just installed), a desktop app (the same engine in a graphical shell), a VS Code extension (a panel inside the editor you’ll install later this chapter), and Claude Code on the web (sessions on cloud machines, from a browser). None of them is wrong. This guide teaches the terminal, for three reasons:

    1. Transparency. Everything they do is a printed line — the log is the conversation. You consent to actions in plain sight.
    2. What you watch, you inherit. Every command they run is one you could run yourself; the friendlier surfaces wrap — which means hide — exactly the part you’re here to learn.
    3. The collaborator lives in your project. A session starts inside a folder, and that folder — files, decision records — is the memory you share. The terminal is where that’s visible, not a metaphor behind a pane.

    The other surfaces are easier to learn after the terminal than before it.

    Your guide, on call — the rule for the rest of this chapter #

    From this line down, every step of this guide has a diagnostician: if anything wedges — an install that errors, a command “not found,” a password prompt you’re unsure about — open a terminal, run claude, and ask. Paste the exact error; exact beats paraphrased, every time. Something like:

    I'm on step setup-homebrew of a setup guide. I ran the install command and got this: [paste the error]. Diagnose it, and tell me what to type — I want to type it myself.

    That last clause is the rule for the rest of this chapter: they diagnose, you type. The tools below are yours — worth installing by your own hand once, because you’ll maintain them for years. It’s also what keeps every walker on one shared path: ten improvised setups would make the verify lines meaningless.

    One distinction for later: what you installed is a helper you can ask. Recruiting a collaborator — mission, consent, a name — is Chapter 3’s different, better thing.

    Install Homebrew ~8 min

    ☰

    Builds on: The terminal

    macOS doesn’t ship a package manager — a single tool that installs, updates, and uninstalls software from the command line. Linux users have had this for decades (it’s the feature that makes a system maintainable rather than a pile of hand-installed apps); Homebrew brought it to the Mac, and nearly everything else in this guide arrives through it in one line each.

    Paste into the terminal:

    /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

    It will ask for your Mac password (typing shows nothing — that’s normal) and may install Apple’s Command Line Tools first. At the end it prints two echo … >> ~/.zprofile lines under “Next steps” — paste those too.

    [Windows — tentative] The closest equivalent is winget (built into Windows 11); choco also works. Tool names below mostly match.

    ✓ You know it worked when: open a NEW terminal window; brew --version answers

    Python, via asdf ~8 min

    ☰

    Builds on: Install Homebrew

    Your Mac has a Python, but it’s Apple’s — old, and risky to touch because the system uses it. The real problem asdf solves is versions over time: projects pin different Python (and Node, and more) versions, and asdf lets any number of them cohabit, switching per-project automatically. (Honest note: nothing in this guide invokes Python — this step provisions the rest of the course, where your harness will want it. If you’re racing the clock, it can wait.)
    brew install asdf
echo '. "$(brew --prefix asdf)/libexec/asdf.sh"' >> ~/.zshrc

    Open a new terminal, then:

    asdf plugin add python
asdf install python 3.12.4
asdf global python 3.12.4

    (The install compiles; a few minutes of scrolling text is expected — fact 2 from the terminal step applies.)

    [Windows — tentative] asdf is Unix-only; the spiritually closest path is winget install Python.Python.3.12 — or WSL2, where everything in this guide works as written.

    ✓ You know it worked when: python --version says 3.12.4

    Visual Studio Code ~4 min

    ☰

    Builds on: Install Homebrew

    The editor where your project’s files, terminals, and the decision records you’ll meet in Chapter 3 all live in one window. Not the only good editor — but the one this guide’s screenshots show, and the one with the extension we rely on.
    brew install --cask visual-studio-code

    Then once: ⌘-shift-P in VS Code → type “shell command” → Install ‘code’ command in PATH. That gives your terminal the code . trick: open any folder as a project.

    A fast terminal: Alacritty (optional, recommended) ~3 min

    ☰

    Builds on: Install Homebrew

    You’re about to spend real time in a terminal, and snappiness compounds — Alacritty is one of the fastest terminals there is, and it has tabs now, which removes the old reason to skip it. (Entirely optional: Terminal.app and VS Code’s built-in terminal both work for everything in this guide.)

    Command-line tools: gh and just ~4 min

    ☰

    Builds on: Install Homebrew

    gh is GitHub’s own command-line client. Chapter 3 uses it to create your project from a template and connect it to your account without ever leaving the terminal — and once you’re logged in with it, every model collaborator you work with can use it too (creating repos, opening issues) on your behalf, with your consent per action. just is a tiny command runner the template relies on — a menu of named recipes per project; you’ll run your first one at the end of Chapter 3.
    brew install gh just
gh auth login

    Pick GitHub.com → HTTPS → login with a web browser, and follow the code it gives you. (No GitHub account yet? Chapter 3 step P1 covers signing up — do that first, then come back for gh auth login.)

    ✓ You know it worked when: gh auth status shows your username, logged in; just --version answers

    VS Code extensions ~4 min

    ☰

    Builds on: Visual Studio Code

    Two small additions make the decision records of Chapter 3 first-class citizens in your editor: ADRs for AI renders them, collects every open question into one view, and lets you answer in place; Terminals Manager relaunches your project’s model sessions in one click (you’ll meet that at the end of Chapter 3).

    In VS Code, ⌘-shift-X, search and install:

    • ADRs for AI (publisher: jlumbroso) — or from a terminal: code --install-extension jlumbroso.adrs4ai
    • Terminals Manager (fabiospampinato) — or: code --install-extension fabiospampinato.vscode-terminals

    Environment complete. Chapter 3 is where it becomes a project.

    ✓ You know it worked when: ⌘-shift-X → “Installed” lists both
